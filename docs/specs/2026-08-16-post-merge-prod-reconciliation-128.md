## Audience

- `PROD_ENV_MERGE` cannot carry a value containing its own sed delimiter, and the failure has TWO forms. Probed directly: the substitution exits 1 with 'unknown option to s' and leaves the file byte-identical. In the SINGLE-KEY relay lanes the failed sed is the last command, so ssh returns 1 and the caller's set -euo pipefail aborts — loud, and the only form reachable today, because those are the only lanes carrying an operator-supplied value. In the MULTI-KEY block the remote loop has no set -e, so a later iteration's exit status overwrites the failed one: the loop exits 0, the lane prints its success line, and the key silently keeps its old value. That silent form becomes reachable the moment `NODES_DATABASE_URL` joins the multi-key block — which is exactly what the settings lane does.
  - honesty: The exact sed substitution from `PROD_ENV_MERGE`, given a replacement line containing a pipe, exits non-zero and leaves the target file byte-identical.

  - honesty: A prod.env that never receives a `DATABASE_SSLMODE` key still yields a fully-resolved sslmode in docker compose config, because the URL carries no placeholder.
