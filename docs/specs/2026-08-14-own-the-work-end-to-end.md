# own-the-work-end-to-end

> Culture Nodes owns a ticket end to end across hosts: work crosses a machine boundary as a portable handle, a deadline stops the session it bounds, and the run explains itself without a companion document.
> instruction: Prove it with one run of examples/pr-upkeep end to end: sweep finds an item, fix produces an artifact:// handle on spark, review consumes it on thor, and the whole thing is legible from GET /v1alpha1/runs/{id} plus its ledger projections with no companion file open.

## Audience

- Three audiences, in the order the work serves them. (1) The OPERATOR running a development cycle through Culture Nodes — today they are the transport (copying bytes between hosts), the memory (writing the state file the ledger could not), and the recovery mechanism (committing a timed-out node's work by hand). (2) A READER WHO WAS NOT PRESENT — a reviewer, a future maintainer, or the same operator six weeks later — who must reconstruct what happened from the run alone. (3) The AGENT FLEET itself, which needs work to cross a host boundary and needs its own attempts attributed well enough that the comparative record means something.
  - instruction: When writing the delivery summary, check each of the three audiences against c35's signals — if the reader-who-was-not-present has no signal that could have failed, say so rather than claiming the audience was served.

## Why it matters

- The human is meant to be the DECIDER, not the plumbing and not the memory. Every hour spent copying bytes between hosts, re-reading a worktree to find out whether a failed run actually failed, or writing down what the ledger could not say, is an hour not spent on the only judgement a human is uniquely needed for. The dogfooding reflex in CLAUDE.md exists to accumulate a comparative record of which actor is better at what — and every grade in that record currently rates an ENDPOINT against an unknown model, so the evidence is weaker than it reads. Fixing that is not tidiness; it is what makes the accumulated record worth anything.
  - instruction: Re-read this before deciding any trade-off that would save engineering time by leaving a human in the transport or recall path — that trade is the thing the batch exists to refuse.

## Decisions

- All eleven named issues are in this batch: #76, #77, #78, #79, #80, #81, #82, #83, #84, #86, and #87 as the umbrella. Decided by the user against a proposed smaller cut. Three constraints do not move and must shape the plan rather than be discovered mid-run: (1) #80 depends on #78 and #77 landing first — a continuation is hollow without preservation, and its model-adaptation half is unmeasurable without model recording; (2) #76's acceptance is fixture-only, because a JQL across the whole Jira site returns zero issues, so its live proof is a separate gate explicitly blocked on backlog content; (3) session accounting per #48 binds the fan-out — the operator window and every bridge session share one pool, so this batch needs a declared model-session count per wave before any assignment.
- The canonical human-inbox unit naming is culture-nodes-\* with a JSON config file: culture-nodes-human-inbox.service reading ~/.config/culture-nodes-bridges/human-ops.json, and culture-nodes-human-inbox-tracker.service reading ~/.config/culture-nodes-bridges/human-ops-tracker.env. No live service is renamed and there is no cutover window.
- q2 is SETTLED by direct measurement against the production database on thor (prod-postgres-1, role nodes, db nodes), read read-only over ssh. #77's write path WORKS: attempt 01M00P2B1CGGGJP63TCDY5F18V, `actor_claude_developer`, succeeded, started 2026-08-14 17:45:40Z, records `usage_model` = 'claude-opus-5\[1m\]'. - q1 decided: the deadline-triggered cancel lives in internal/scheduler, which gains an actor Registry and Client. Rationale, in the order it weighed: (1) failWaitingExternal already holds the PendingInvocation — with ActorRef, ActorID and InvocationID on it — at exactly the seam where the cancel belongs, so no new lookup is needed and cancelPendingInvocation's first step is work already done; (2) the cancel MUST be issued before CompleteAttempt commits, and only the scheduler is at that seam — any handback makes the cancel asynchronous precisely where the concurrent-writer hazard lives; (3) cancel is best-effort by contract (PRD 13.6), so a scheduler that cannot reach a bridge degrades to a recorded failed-propagation event exactly as the other three callers do, never to a broken timeout. Shape: mirror the existing per-namespace engineFor cache with a registryFor, and use a package-level actors.NewClient() the way internal/api/cancelpropagate.go does. Accepted cost: bridge egress from a process the prod compose provisions database-only (`NODES_DATABASE_URL` and `NODES_SCHEDULER_ID` only), which is a deployment-posture change the deploy lane must carry.
- q3 decided: the deadline's Cancel is issued AFTER fireOne commits, off the transaction, and the re-dispatch race is closed by FENCING rather than by ordering. This supersedes the ordering half of decision c38 while leaving its seam half intact — the cancel still originates in internal/scheduler, it simply no longer sits inside applyEffect's transaction. Rationale: PRD 13.6 already makes cancellation best-effort and explicitly says workflow state does not depend on an external process acknowledging it, so a post-commit cancel loses nothing the contract promised; the scheduler never blocks a serial, singleton, batch-of-100 timer loop on a bridge that #21 measured at >10s mid-session; and the window c42 opens — `timed_out` is retryable, so a second dispatch can begin before the cancel lands — is closed by refusing a dispatch into a workspace whose prior session is not confirmed stopped, which is #82 point 3's own alternative ('or fence the workspace so a second writer is refused'). The accepted cost is that the fence does not exist and must be built in this batch.
- q6 decided: a fired deadline consults a declared continuation condition before cancelling. If the node declared one (#80's continue.while, evaluated in CEL by the engine like every other condition) and it holds, the deadline PAUSES — the session stays warm, its `continuation_ref` intact, charging nothing against budget.maxSessions per ADR 0010. If the node declared none, or the condition does not hold, the deadline CANCELS as #82 requires. This makes #82 and #80 compose instead of collide, and it uses #80's own declared-condition design rather than inventing a second mechanism. Accepted cost, stated plainly: #82 can no longer ship independently of a minimal slice of #80 — the schema for the declaration, its compilation, and its evaluation must exist before the deadline handler is complete, which re-orders the batch (see the amended c21).
- q7 decided, and NOT by any of the three options offered — the operator replaced the question. Rather than trying to prove the unverifiable process claim 'the test failed first', the handover contract becomes a set of DETERMINISTIC, TOOL-MEASURED quality gates on CHANGED FILES: test coverage, cognitive complexity, and file-size validation, plus the existing test suites. These must pass BEFORE handover. Agent-authored tests and fixes are accepted AFTER handover and merge. Why this is stronger than what it replaces: a coverage number, a complexity score and a file size are facts a deterministic validator measures, which under the PRD ledger authority model land as DERIVED records — a higher authority class than the proposed self-report c53 would otherwise have rested on — and they need no part of #13, so the batch stays at eleven. It also changes what TDD is FOR here: the gate stops asking when the test was written and starts asking whether the changed code is adequately covered and adequately simple, which is the property anyone actually wanted.

- A lacking or failing test is a DECISION THAT ROUTES TO A CONTINUATION, not a technical failure. This binds the q7 handover contract to the q6 deadline decision and to #80: when a handover gate does not pass — tests failing, coverage under threshold, a file over the length limit — the node does not end 'failed'; it produces a routable domain outcome that the workflow author has declared an edge from, and the natural edge is a continuation that fixes it.
