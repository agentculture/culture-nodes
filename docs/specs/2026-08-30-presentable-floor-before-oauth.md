# presentable-floor-before-oauth

> Culture Nodes is presentable and operable from Jira and its own site: the 5-minute sweep runs green again and a failed sweep names its reason where an operator looks; pending human decisions are collected in one view with up to 3-4 options each, echoed onto the Jira ticket, and stale ones expire when their PR merges; repeat sweep runs no longer bury real work in the runs list; the site's four visible defects are fixed and every ticket has a reachable page link; the backlog is honest — every issue that no longer reproduces is closed on evidence and every big feature is a named issue — and every fix package in this cycle is assigned through culture-nodes itself. This is the clean floor before the OAuth / login-from-anywhere cycle.

## Audience

- Three readers: a human on the Jira board and the ticket page who has never opened a shell (files a ticket, answers a question, decides an approval from the options offered); an agent actor (codex-thor/orin, developer) that picks up an assigned package and reports back through the ledger; and the operator who reads the runs list, the collected decisions view and the backlog and must see real work first, not fifty red sweeps

## Before → After

- Before: Today: the sweep was dead for 16 hours with no visible reason and 184 red runs on the first screen; 27 pending decisions sit in a 113k-px page nobody is paged to, 26 of them for PRs already merged, four of them duplicates of one finding; the ticket page link is a bare path; a Done ticket still has a running spec-chain; agents cannot see the ticket description; the stats tile says 588%; the backlog has six issues whose closing evidence already exists and twelve one-hour fixes waiting behind them; README and the guide never mention Jira
- After: After: the runs list opens on real work with sweeps collapsed under a counter; a failed node names its reason on the run page; the Decisions view lists every pending decision with 3-4 options and the same options are on the Jira ticket, the ticket page and Discord; stale approvals expire on merge; every ticket carries an absolute page link and its page shows 'Open in Jira'; freeze ends the ticket's runs; agents receive the ticket description; the four site defects and the polish bundle are shipped; six issues are closed on cited evidence, twelve on landed fixes, three on decision records, and every remaining big feature is a typed issue; a docs page tells a human how to drive the loop from Jira; and every fix package cites the culture-nodes run that produced it

## Why it matters

- The OAuth / login-from-anywhere cycle puts the site and the ticket page in front of people outside the LAN; it should open onto a floor that is green, legible and honest, and the credential-dependency list this cycle records is that cycle's input — otherwise the first thing a new login sees is a wall of failed sweeps and a decisions page it cannot scroll
