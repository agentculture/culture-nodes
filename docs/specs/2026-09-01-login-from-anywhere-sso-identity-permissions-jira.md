# login-from-anywhere: sso, identity, permissions, jira coverage

> Culture Nodes is reachable at nodes.culture.dev behind Cloudflare Access SSO on the same Zero Trust team as chat.agentculture.org; every person who signs in is a named human actor and every agent or bridge holds its own API token, and the ledger stamps origin from the authenticated caller rather than a request field; a ticket's human tasks, proposed claims and confirmations are decided on its own page under that identity; agents can read a Jira ticket's body, comments and links, and the system moves the board itself: In Review on a PR, Pending on a parked question, Done when a human says so after live validation. OIDC / Entra workload auth is scoped as the follow-on.

## Audience

- Three audiences: (1) people who decide — the operator today, and anyone allowlisted by email in the Access policy tomorrow — who open a ticket link from Jira or Discord from anywhere and decide on the page; (2) agent and bridge actors (codex-thor/orin, claude, jira, notify, human-inbox) whose completions must be attributed to the credential that made them; (3) the operator running the lanes, who stops handing out one shared secret and stops being the system's Jira identity

## Before → After

- Before: As of 2026-08-30 (docs/audits/2026-08-30-lan-and-credential-dependencies.md, corrected): thor:18080 is HTTP-only on LAN/tailscale with no auth middleware on any GET; one shared `NODES_HUMAN_DECISION_TOKEN_SECRET` gates page replies, frame posts, freeze, human-task decisions, reviews, suite verdicts and gate reports, while POST /runs/{id}/grades is not gated at all (the audit's line saying otherwise is inaccurate); identity is a free-text replier/`decider_actor_id` nobody binds to a person; one personal Jira Basic-auth pair (the operator's account) is the sweep, the bridge and both operator skills, so the operator's own board actions are filtered as self-echo
- After: Opening <https://nodes.culture.dev> from any network redirects through Cloudflare SSO and lands a signed-in person on what is waiting for them; every decision, reply, review and grade carries that person's identity as the ledger origin; every bridge completion carries the actor the credential belongs to; no human holds `NODES_HUMAN_DECISION_TOKEN_SECRET`; an agent can read the Jira ticket it works on; the board moves to In Review when a PR opens, Pending on a parked question, Done on merge, without an operator hand-turn; the ticket page decides everything and looks like a guided flow rather than a wall of lists

## Why it matters

- The presentable-floor cycle left a floor that only the LAN can reach and only one shared secret can write to; every decision the system asks for is answered by whoever holds that secret under a typed-in name, so the ledger's authority model (agents propose, humans confirm) is a convention the transport does not enforce (#117/#183/#6). Putting the site in front of people from anywhere is impossible until identity is real, and the Jira loop is blind (agents cannot read tickets) and half-manual (Done and In Review are hand-turns counted in #118)

## Scope / boundaries

- Cloudflare Access is the ONLY human login surface: no OAuth client, session cookie, password or user table lives in the control plane; identity arrives as a verified JWT claim and the control plane only decides which registered actor it maps to. OIDC/Entra token validation for API callers and workload callbacks (#6, docs/decisions/issue-6-oidc-workload-authentication.md) stays the named follow-on issue, not this cycle's build
- Board-state custody stays bridge-enforced (docs/decisions/2026-08-18-jira-transition-custody.md): widening from one target to a per-transition allowlist changes `JIRA_TRANSITION_`\* bridge configuration and a restart, never a workflow document or actor prompt, and the project-prefix guard is kept
- Grading stays out of #255's first cut beyond gating the route: there is no grades UI in web/src at all, and POST /runs/{id}/grades is unauthenticated today, so the cycle gates it with the same principal check but does not build a grading page
- devague confirmations stay in the custody checkout on spark this cycle: internal/devague.MapFrameClaims has no production caller and the live path is an opaque `frame_json` blob (tickets.go:261), so the ticket page displays frame claims and their confirmation state but does not run devague confirm
- Unchanged Jira invariants: the credential pair stays env-only and out of every config/compose file (config.py:11-20, tests/deploy/`jirabridgeaudit_test.go`); the sweep keeps zero write path; allowlists are configured never defaulted and matched exactly; a workflow literal cannot widen custody; comment precedes status move; no decision-token material enters a fan-out payload; page-reply and sweep comment facts keep one schema and `jira_comment_is_self_echo` stays uncarved
- Untouched: internal/actors/token.go (attempt-scoped HMAC, deliberately not a JWT), the unversioned callback and runner-callback routes every minted callback.url points at, the dial-in issuance lifecycle, actors.metadata.`auth_token_env` and the no-secret-at-rest rule, append-only actors and ledger, internal/awsauth (IRSA is workload identity for the AWS lane), bridge-side `_require_auth` and /v1/capabilities auth, the artifact-read posture decision, and the review transaction that turns proposed into confirmed

- TLS terminates at Cloudflare's edge and the tunnel carries traffic to prod-api-1 over the host; no ListenAndServeTLS, cert flags or reverse proxy are added to cmd/nodes/serve.go, and the LAN listener on 18080 keeps working for the sweep, workers and bridges that use `NODES_API_URL`/`NODES_CALLBACK_BASE_URL` as LAN IPs

## Decisions

- Human identity comes from Cloudflare Access at the edge rather than an OIDC client inside the control plane: it reuses the org's existing Zero Trust team, tunnels and cultureflare provisioning, needs no dependency, and leaves #6's workload/OIDC half as a separate follow-on with its own issuer/audience decision
- Done on merge is a human actor node: a merge raises a human decision after live validation, and a ticket moving to Done is a possible result of that node — never an automatic transition from the merge fact
- The UX uplift is in this cycle and every surface is reflected on the web: a surface is retired only when a better UX replaces it in that tab, a new one, or an existing one; the UX insights are aggregated on a new Feature issue
- Pending is the canonical waiting status; the spec's 'Waiting for decision' wording is retired, no board column is added
- A dedicated system Atlassian account is provisioned by the operator for the bridge, the sweep and `jira_bot_account_id`, so the operator's personal account becomes a human again; the recipe is docs, no code
- The SSO principal binds to an actor through a separate `actor_identities` table keyed by (provider, subject) — never by email column or the owners table — because bot and service identities may carry fake emails
- Roles shipped first: approver (decide, review, reply) and namespace administrator (register actors, publish, cancel, schedules, credentials); every other principal is a viewer
- UX scope: the human-facing pages (ticket, inbox, decisions, header, first visit) are redesigned in this cycle; for non-human-facing surfaces (runs, ledger, graphs, mesh, stats) the agent decides — kept, touched only where the same components are reused, retired only when replaced
- q3 proposal: the ticket page submits one review per run in sequence, rendered as one action with per-run results, so a person never has to know the ledger is per run; a stale run is reported individually and the others still commit
- q4 proposal: #257 is a `read_issue` verb on the jira bridge (fresh at node time, same custody shape as the write verbs) rather than richer sweep facts
- Jira push uses a system webhook rather than an Automation rule: the tenant's 1,000 Automation runs/month come from a Premium trial that ends soon, so the receiver accepts a webhook at a dedicated path exempted from Access by a path-scoped Bypass policy and verifies a shared secret on every delivery
