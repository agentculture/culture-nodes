> Culture Nodes accounts for every attempt and orchestrates humans, loops, and itself: failed attempts carry actor attribution and usage; evidence bindings resolve real run evidence and bridge-measured diffs; nodes pre-announce success criteria that are mechanically checked; humans execute nodes through the same lifecycle as agents; ad-hoc runs are first-class; and the system proves it live with a PR-upkeep flow sweeping Qodo and SonarCloud findings on this repo

## Audience

- Operators of the culture-nodes control plane (Ori and mesh operators with the nodes-operator skill), workflow authors, the registered actor fleet (claude-code bridge on spark, codex-thor, codex-orin, future human actors), and the per-actor analytics consumers of issue 28

## Decisions

- Steady state after delivery: the PR-upkeep loop runs periodically with its nodes executed by human actors or code nodes — picking up PRs that need conflict resolution, review-comment handling, or SonarCloud fixes — agent bridges are an option, not a requirement
- Human nodes get a background tracker: while a human-actor attempt is parked, a tracker periodically asks the assigned human for an update and posts progress back to the run (the update surface rides the human-inbox bridge; nudge cadence authorable). The concrete Discord/Slack nudge transport is deferred to its own issue — a discord-cli solution exists for the integration
- Graph model (design direction, confirmed): node flows and node loops are one thing — graphs that split, diverge, and reconnect, where each node has many outcomes. Continuation comes in two kinds: scripted (a fixed, configured edge set — today's compiled edges) and event-based (a node emits an event any node can pick up and continue from, including splits). Emission is non-blocking: a node may emit an event mid-execution and continue working — e.g. an agent node calls a human node for a reply while the agent keeps going. Implementation of parallel tokens/split-join is DEFERRED (non-goal c18 stands for this batch); the c10 wait/signal surface is shaped event-first (first-class, subscribable events, not point-to-point resume) so it is forward-compatible with this model
